# Documentazione funzionale

Cosa fa l'app, schermata per schermata e regola per regola. È il documento che chi sviluppa apre per sapere **come si deve comportare** una funzione, e che chi guarda il progetto dall'alto apre per sapere **cosa c'è dentro**.

Non contiene scelte tecniche: quelle stanno in [`../tecnico/`](../tecnico/). Non contiene il perché delle scelte: quello sta in [`../decisioni/prodotto.md`](../decisioni/prodotto.md) e nella discovery.

## Come è scritto ogni capitolo

Sempre la stessa struttura, perché sia prevedibile da leggere e da riempire:

1. **A cosa serve** — una frase
2. **Schermate** — cosa vede la persona
3. **Regole di comportamento** — numerate, verificabili, senza ambiguità
4. **Casi limite** — cosa succede quando le cose vanno storte
5. **Cosa resta fuori** — i confini, per evitare che qualcuno li superi in buona fede
